Cyber Kill Chain

  • Reconnaissance -> collecting information about system.
  • Weaponisation -> the attacker creates some payloads.
  • Delivery -> the attacker sends the weaponized payload.
  • Exploitation -> the payload exploits a vulnerability in the target system.
  • Installation -> the payload exploits a vulnerability.
  • Command & Control(C2) -> using the installed backdoor.
  • Actions on Objects -> the attacker can now carry out further actions.

FTP → FIle transfer protocol

  • FTP send data in cleartext for this reason we use:
  • STFP → SSH FILE TRANSFER PROTOCOL
  • FTPS → FTP Secure adds TLS encryption to the FTP protcol on 990
  • SCP → Secure Copy Protocol also runs over SSH
  • STAT → additional information
  • SYST → SYSTEM TYPE OF THE TARGET
  • PASV → passive mode
  • In active mode data sends over on port 21 WAF and firewalls sometimes drops it. In passive mode data send over on port 1023 this is more firewall-friendly.
  • TYPE A → switches the file transfer mode to ASCII while TYPE I switches the file transfer mode to binary.
  • USING an FTP client:
    • ls → lists the files,

  • SSL and TLS in Presentation Layer
  • Man-in-the-Middle(MITM) attack

  • DNS Spoofing -> involves providing false DNS response to redirect victims to attacker-controlled servers.
  • Rogue Access Points -> are fake wireless access points set up by attackers. When victims connect to these networks all their traffic flows through the attacker's system.

SSH Key Generation ->

  • to set up key_base authentication, generate a key pair using ssh-keygen:
  • ssh-keygen -t ed25519 -C "my_email"
  • ssh-keygen -t rsa -b 4096 -C "my_email"
  • our private key is stored in ~/.ssh/id_ed25519 (or ~/.ssh/id_rsa)
  • To enable key-based login on a server, add your public key to the ~/.ssh/authorized_keys file on the remote system: ssh-copy-id mark@10.113.167.16
# Connect on a non-standard port
ssh -p 2222 mark@10.113.167.16

# Use a specific private key

# Jump through a bastion/jump host to reach an internal server
ssh -J bastion.example.com mark@internal-server

# Local port forwarding (access remote service through local port)
ssh -L 8080:localhost:80 mark@10.113.167.16

# Dynamic port forwarding (SOCKS proxy)
ssh -D 9050 mark@10.113.167.16

# Run a single command without interactive shell

Nmap

  • Subnets with /16, which means that the subnet mask can be written as 255.255.0.0
  • Subnets with /24, which indicates that the subnet mask can be expressed as 255.255.255.0
  • ARP scan is possible only if you are on the same subnet as the target systems.
  • nmap -PR -sn TARGETS, where -PR indicates that you only want an ARP scan.
  • it is wise to keep in mind that many firewalls block ICMP.
  • However, rDNS records aren’t always configured or accurate, so results may be missing or misleading.
  • I can use -R to start a reverse dns on nmap.
  • Note that we can use -F to enable fast mode and decrease the number of scanned ports from 1000 to 100 most common ports.
  • don't use T5 you can use T4 instead.
  • For example, --max-rate 10 or --max-rate=10 ensures that your scanner is not sending more than ten packets per second.
  • For instance, --min-parallelism=512 pushes nmap to maintain at least 512 probes in parallel; these 512 probes are related to host discovery and open ports.
  • The null scan does not set any flag; all six flag bits are set to zero. You can choose this scan using the -sN option.
