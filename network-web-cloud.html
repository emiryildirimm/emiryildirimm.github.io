Networking, Web & Cloud Concepts

March 12, 2026 Web / Cloud ~12 min read

A deep dive into how the internet works under the hood. Containing all exact notes regarding common ports, DNS resolution, web architectures, load balancing, and cloud models.

Common Ports

FTP -> 21
SSH -> 22
HTTP -> 80
HTTPS -> 443
SMB -> 445
printers use this port mostly
RDP -> 3389

Firewalls and Tunnels

Firewall Categories ->

  • Stateful -> device based firewall it will block the entire device.
  • Stateless -> This firewall type uses a static set of rules to determine whether or not individual packets are acceptable or not.

Tunnels & Segmentation

  • PPTP -> Point to point Tunneling Protocol -> is the technology that allows the from PPP to travel and leave a network.
  • IPSec -> Internet Protocol Security -> encrypts data using the existing IP framework.
  • VLAN -> (Virtual Local Area Network) -> allows specific devices within a network to be virtually split up. Two other departments will be able to access the internet but not able to communicate with each other although they are connected to the same switch.

domains ->

  • for example tryhackme.com is a domain
  • .com .edu .gov these are TLD stands for Top Level Domain
  • uk .ca .tr these are ccTLD -> country code Top Level Domain
  • tryhackme is a second-level domain
  • and admin.tryhackme.com is a Subdomain which means admin page of the tryhackme

DNS Record Types

  • A Record -> These records resolve to ipv4 addresses.
  • AAAA Record -> These record resolve to ipv6 addresses.
  • CNAME Record ->
  • MX Record -> These records resolve to the address of the servers that handle the email for the domain you are querying.
  • TXT Record -> TXT Records are free text fields where any text-based data can be stored.

making a DNS request

  • 1 - first my computer first checks its local cache to see if you've previously looked up.
  • 2 - Recursive DNS Server is usually provided by my ISP. This server also has a local cache of recently looked up domain names.
  • 3 - Root DNS Server -> backbone of the internet their job is to redirect me to correct Top Level Domain Server.
  • 4 - authoritative server -> TLD servers hold records for where to find the authoritative server to answer the DNS request for example cloudflare.com serves as a authoritative server.

nslookup(name server lookup) -> it helps me discover the IP address linked to a domain name. Find which domain owns an IP address.

Web Protocols & URL Anatomy

HTTP in Detail

HTTPS provides us encrypted data.

What is URL

  • https:// -> what protocol to use for accessing the resource.
  • user:password -> some services require authentication to log in.
  • tryhackme.com -> host -> the domain name or ip.
  • :80 -> The port that I am going to connect to.
  • path -> The file name or location of the resource I am trying to access.
  • Query string -> ?id -> extra bits of information.
  • Fragment -> #task -> this is commonly used for pages with long content and can have a certain part of the page.

HTTP Status codes

  • 100-199 -> Information Response
  • 200 - 299 -> Success
  • 300-399 -> Redirection
  • 400-499 -> Client Errors
  • 500-599 -> Server Errors
200 -> ok

302 -> Found
400 -> Bad request
401 -> Not Authorised
403 -> Forbidden
405 -> Method Not Allowed
404 -> Page Not found
500 -> Internal Service Error
503 -> Service Unavailable

Web Infrastructure

  • Load balancers -> load balancers provide two main features, ensuring high traffic websites can handle the load and providing a failover if a servers becomes unresponsive.
  • round-robin -> this algorithm sends it to each server in turn.
  • weighted -> sends it to the least busy server.
  • Load balancers also perform periodic checks with each server to ensure they are running correctly, this is called a health check.
  • CDN -> Content Delivery Networks -> It allows you to host static files from your website and host them across thousands of servers all over the world.
  • Databases : Often websites will need a way of storing information for their users.
  • WAF -> A WAF sits between your web request and the web server; its primary purpose is to protect the webserver from hacking or denial of service attacks.

Cloud Models

  • IaaS -> Infrastructure as a Service -> You rent basic computing resources such as virtual servers, storage and networking -> Renting a empty apartment.
  • PaaS -> Platform as a Service -> You focus on building, deploying, and running your application without worrying about servers. Renting a semi-furnished apartment.
  • SaaS -> Software as a Service -> You use a complete application over the internet. For example Gmail or Zoom -> Staying in a hotel.
